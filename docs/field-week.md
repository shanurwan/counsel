# Field run: issue triage on real repositories

From 08 Nov 2026 to 08 Nov 2026 16:30 UTC, Counsel's `issue_triage` agent read every new issue on `shanurwan/counsel` and wrote a triage draft. On the author's own repositories the owner reviews each draft and publishes or rejects it. Everywhere else it is **shadow mode**: nothing is posted to GitHub, labelled or assigned, and the drafts stay in Counsel's database. Then each draft is compared with what the maintainers actually did. Generated by `counsel field`.

## What it found

- **4 issues triaged**, 0 of them acted on by a maintainer so far (a reply, a label or closing it).
- **Reviewed by the repository's owner:** 4 drafts on `shanurwan/counsel`: 4 published as written, 0 rejected. Only owners who review drafts count here: the author on their own repositories, and maintainers who installed the triage app.
- **Duplicates:** the drafts named a duplicate on 0 issues; maintainers agreed on 0. Maintainers closed 0 as duplicates; the drafts missed 0 of those.
- **Missing information:** maintainers asked a reporter for more on 0 issues; the draft had already flagged something missing on 0 of them. On 0 issues a maintainer acted without asking for more although the draft said something was missing.

How the comparison is made: a duplicate counts when GitHub records the issue as closed as a duplicate or marked as one. A maintainer is the owner, a member or a collaborator. "Asked for more" is read from their comments and labels with a pattern, so read the table below rather than trusting the counts alone.
